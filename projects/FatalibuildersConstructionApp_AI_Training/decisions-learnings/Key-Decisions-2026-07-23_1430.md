## Decisions

### 1. Raw company files are NOT stored in the repository (owner decision)
- **Decision:** The owner rejected copying the three uploaded files (2026 rate card xlsx, Thika Mosque BOQ pdf, weekly work log xlsx) into the memory repo. Only the **extracted data** is retained.
- **Rationale:** This AI_Memory_Open fork is PUBLIC — raw company documents don't belong there. (Reinforces the need to migrate the app to the private `fatalibuilders-app` repo.)
- **Impact:** Rates embedded in code as the product's baseline price table (they surface in the product anyway); BOQ format captured as a design spec; labor day-rates recorded below. Raw files live only with the owner.

### 2. Cost engine prices by WORK-ITEM rates, not raw material prices
- **Decision:** The owner's rate card prices complete work items (e.g., "Concrete slab m³ = 5,200 labour / 17,000 full") — the cost engine adopts this model directly instead of material-price × quantity + labor separately.
- **Rationale:** Matches how Kenyan contractors actually quote; the card is owner-authoritative; simpler and more defensible than synthetic material pricing.
- **Impact:** `engines/cost/` computes a BOQ-style estimate from the materials engine's machine-readable measures. **Dual mode retained from the card: full contract vs labour-only** — a distinctive product feature.

### 3. Features retained from the owner's documents (per owner instruction "retain some features")
