# Key Decisions — 2026-07-16 1019

**Session Goal:** Record the owner's full core-tool definition and sequence the resulting scope.

## Decisions Made

### Decision 1: Core tool = ALL calculators + drawings + engineering outputs (RESOLVES the blocking open question)
- **Context:** The owner was asked what data goes in and what results come out.
- **Decision:** Owner confirmed "all the above" (material quantities, cost estimate, labor/time estimate) **plus** 2D drawings, renders, structural drawings, and a geotechnical report once the soil type is entered.
- **Rationale:** Owner directive.
- **Impact:** Document 1's core definition is complete. Epics restructured into 8 (input flow, calculators, output/sharing, drawings & visuals, engineering outputs, product site, plus pending management features). A single structured project-data input flow (Epic 2) feeds all outputs.

### Decision 2: Engineering outputs must carry "preliminary — licensed engineer review required" safeguards
- **Context:** Structural drawings and geotechnical reports are professional engineering deliverables; in most jurisdictions they require a licensed engineer's review/stamp before construction use. Auto-generated versions used directly could endanger buildings and expose Fatali Builders to liability.
- **Options Considered:** (a) Exclude these outputs; (b) include them raw; (c) include them clearly marked as preliminary/indicative with disclaimers at generation and on every export, with legal review before that release.
- **Decision:** Option (c).
- **Rationale:** Honors the owner's scope while protecting end users' safety and the company's liability. The owner is an engineer and can validate the rule-sets used.
- **Impact:** Legal dependency now includes professional-liability disclaimers (mandatory before Release 3); engineering outputs watermarked; geotechnical report framed as soil-type-based guidance.

### Decision 3: Phased releases — calculators first, drawings second, engineering outputs third
- **Context:** The confirmed scope spans very different difficulty levels: calculators (straightforward), 2D drawing generation (moderate-hard), renders (hard), structural/geotech generation (hard + regulated).
- **Decision:** Release 1 (MVP) = accounts + payment + input flow + calculators + Excel/WhatsApp/PDF outputs + product site. Release 2 = 2D drawings, then renders. Release 3 = structural drawings + geotechnical report. Release 4 = management features if kept.
- **Rationale:** Gets a sellable $30 product to market fast; hardest and highest-liability features get the time they need without blocking revenue.
- **Impact:** Document 3 (Release Plan) now has its skeleton; Document 2 must design the input data model to support ALL future outputs from day one (so no re-entry is needed when drawings arrive).

## Learnings & Insights

- **Learning 1:** The single most important design artifact is the **project-data input model** — every output (quantities, costs, labor, drawings, structural, geotech) derives from it. Getting it right in Document 2 prevents rework across all releases.
