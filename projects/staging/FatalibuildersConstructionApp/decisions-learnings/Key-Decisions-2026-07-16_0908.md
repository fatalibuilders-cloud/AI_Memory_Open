## Decisions Made

### Decision 1: Integration-first architecture — "integrate with all kinds of tools"
- **Context:** Staging had an open question about which existing tools the app must integrate with or replace.
- **Options Considered:** (a) Closed internal tool with no integrations; (b) a fixed shortlist of integrations; (c) integration-first architecture designed to connect to all kinds of tools.
- **Decision:** Option (c) — owner directed the app to "integrate with all kinds of tools" (2026-07-16).
- **Rationale:** Owner's explicit instruction. Construction workflows span accounting, CRM, messaging, documents, and field services; an API-first core with connector modules avoids repeated re-architecture as tools are added.
- **Impact:** Document 2 (Architecture/Design) moved to In Progress. System architecture must be API-first with webhooks and MCP-style connectors. A candidate integration list (accounting, CRM, productivity, messaging, field services) was drafted for prioritization.

## Learnings & Insights

- **Learning 1:** "All kinds of tools" is a direction, not a scope — a prioritized integration shortlist is still needed to keep release 1 buildable. Prioritization added as a next action.
