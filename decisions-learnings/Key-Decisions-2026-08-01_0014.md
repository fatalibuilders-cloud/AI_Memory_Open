**Session:** Built `deriv-crypto-bot` — a crypto-only, 24/7 trading bot for the Deriv WebSocket API
**Model:** claude-opus-5
**Scope:** AI Memory System (root level) + `app-src/`

## Decisions

- **"Deriv" resolved to Deriv.com, the online broker.** The one-word task brief matched nothing in the memory system; the owner clarified it as a request for a crypto-only 24/7 trading bot.

- **Built directly under `app-src/deriv-crypto-bot/` rather than through `staging.md`.** The request was a concrete build instruction, not a planning exercise, and `app-src/` is already where application source lives. If the bot later becomes a product rather than a personal tool, it can be staged and promoted then.

- **Python, not the repo's existing TypeScript/Next.js stack.** The bot is a headless daemon with no relationship to the construction app. Python is conventional for this class of program and introduces no coupling between the two codebases.

- **Demo account is the default and real money requires explicit opt-in.** The bot inspects `is_virtual` on the authorize response and refuses to start on a real-money account unless `DERIV_ALLOW_REAL_MONEY=true`. The check fails closed: a response missing `is_virtual` is treated as real, not demo.

- **Crypto-only is enforced at three independent points, not one.** (1) The universe is filtered to `market == "cryptocurrency"`; (2) an operator-supplied allowlist is still subject to that filter, so naming a forex pair drops it with a logged error; (3) a final check runs immediately before every purchase. A single filter is one edit away from being bypassed; three make the invariant hard to break accidentally.

- **Nothing about the Deriv API is hardcoded.** Symbols, contract types, and duration bounds are discovered at runtime via `active_symbols` and `contracts_for`, then validated by a live `proposal` before purchase.

- **Polling rather than streaming subscriptions.** Slightly less immediate, but reconnection is a redial with no subscription state to rebuild.

- **The daily halt is persisted to disk.** Without this, restarting the process would clear a triggered loss limit — making the limit unenforceable by the person most motivated to ignore it.

- **The stake is the minimum of three bounds:** the configured `STAKE`, `MAX_STAKE_FRACTION` × balance, and the remaining daily loss budget. No single trade can carry the account past the daily limit.

## Learnings

- **The sandbox has no outbound access to Deriv's documentation** (proxy returns 403 on CONNECT). This turned out to improve the design: rather than encoding API details from memory that could not be verified, the bot discovers them at runtime, which is more robust against Deriv changing symbols or duration minimums.

- **Runtime discovery is the right answer to unverifiable external contracts generally.** Where a remote API's specifics cannot be confirmed, querying for them beats guessing — and the resulting code adapts to upstream change without an edit.

- **A test helper's positional parameter named `symbols` collided with a config field of the same name**, producing `TypeError: got multiple values for argument`. Renamed the helper parameter to `universe`. Worth noting because the collision was invisible until a test passed both.

- **Sequencing tests around indicator warm-up is fragile if you hand-compute the exact bar a crossover lands on.** Walking a price series forward and asserting on the signals produced is both more readable and less brittle; filter tests then reuse the first signalling window and vary only the threshold under test.
