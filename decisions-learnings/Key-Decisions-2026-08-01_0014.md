# Key Decisions & Learnings — 2026-08-01 00:14 UTC (Root Level)

**Session:** Built `deriv-crypto-bot` — a crypto-only, 24/7 trading bot for the Deriv WebSocket API
**Model:** claude-opus-5
**Scope:** AI Memory System (root level) + `app-src/`

---

## Decisions

- **"Deriv" resolved to Deriv.com, the online broker.** The one-word task brief matched nothing in the memory system; the owner clarified it as a request for a crypto-only 24/7 trading bot.

- **Built directly under `app-src/deriv-crypto-bot/` rather than through `staging.md`.** The request was a concrete build instruction, not a planning exercise, and `app-src/` is already where application source lives. If the bot later becomes a product rather than a personal tool, it can be staged and promoted then.

- **Python, not the repo's existing TypeScript/Next.js stack.** The bot is a headless daemon with no relationship to the construction app. Python is conventional for this class of program and introduces no coupling between the two codebases.

- **Demo account is the default and real money requires explicit opt-in.** The bot inspects `is_virtual` on the authorize response and refuses to start on a real-money account unless `DERIV_ALLOW_REAL_MONEY=true`. The check fails closed: a response missing `is_virtual` is treated as real, not demo.

- **Crypto-only is enforced at three independent points, not one.** (1) The universe is filtered to `market == "cryptocurrency"`; (2) an operator-supplied allowlist is still subject to that filter, so naming a forex pair drops it with a logged error; (3) a final check runs immediately before every purchase. A single filter is one edit away from being bypassed; three make the invariant hard to break accidentally.

- **Nothing about the Deriv API is hardcoded.** Symbols, contract types, and duration bounds are discovered at runtime via `active_symbols` and `contracts_for`, then validated by a live `proposal` before purchase.

- **Polling rather than streaming subscriptions.** Slightly less immediate, but reconnection is a redial with no subscription state to rebuild.

- **The daily halt is persisted to disk.** Without this, restarting the process would clear a triggered loss limit — making the limit unenforceable by the person most motivated to ignore it.

- **The stake is the minimum of three bounds:** the configured `STAKE`, `MAX_STAKE_FRACTION` × balance, and the remaining daily loss budget. No single trade can carry the account past the daily limit.

- **Backtesting drives the live code rather than reimplementing it.** `backtest.py` calls the same `strategy.evaluate` and `risk.RiskManager` the trader does, over a trailing window of exactly `CANDLE_COUNT` candles — which is what the live bot fetches each cycle. A backtest therefore exercises the real decision path. Two small changes enabled this: `StateStore(persist=False)` for in-memory accounting, and an optional `now` on `RiskManager.refresh_daily_limits()` so daily limits roll over on historical timestamps.

- **The backtest report leads with breakeven win rate, not win rate.** With a 0.85 payout a win gains 0.85 and a loss costs 1.00, so 54.05% accuracy is required merely to break even. Presenting win rate alone would make a 51% result look "nearly profitable" when it is decisively losing. The report prints both side by side and flags anything within 2 points of breakeven as MARGINAL.

- **A preflight check is the onboarding path, not the README.** `python -m deriv_bot.check` verifies token, account type, universe, data, strategy, and contract pricing, and reports READY/NOT READY with a specific remedy per failure. It never buys — it requests a quote and stops, with a test enforcing that. For a first-time builder this replaces "read the docs and hope" with one command that says what is wrong.

- **The check measures the payout ratio rather than assuming it.** A live proposal yields the real ratio, which the check prints as a ready-to-paste `--payout-ratio` argument. This closes the loop on the backtester's largest documented assumption.

- **Socket-open failures are translated to `ConnectionLost` at the API boundary.** Callers should not have to know the `websockets` exception hierarchy. This was not a stylistic choice — see the learning below.

- **Scope narrowed to Bitcoin only, by configuration rather than by code.** The owner asked for Bitcoin only. Implemented as `DERIV_SYMBOLS=BTC` (now the default in `.env.example`) rather than hardcoding a ticker, so widening back to all crypto is a one-line edit and the crypto-only invariant stays the deeper guarantee.

- **Symbol aliases are resolved against Deriv's live listing, not matched literally.** `BTC`, `BTC/USD`, and `cryBTCUSD` all resolve to the same market. Deriv's exact spelling could not be verified from the build sandbox, and requiring the owner to know it would turn one typo into a silently empty universe. Resolution runs *after* the crypto filter, so an alias can never reach a non-crypto symbol however it is spelled.

- **Strategy comparison ships with controls, not just strategies.** `always_call` (buy-and-hold analogue), `coin_flip` (noise floor), and `never_trade` (cannot lose) sit in the same ranking table as the real rules. Without them a comparison always crowns a winner, however meaningless. With them, the report can say "nothing beat not trading" — which is what the data actually said.

- **Contract length is a bigger lever than the indicator.** A duration sweep is now a first-class command (`--sweep-durations`). Directional drift accumulates linearly with time while noise grows with its square root, so the same rule that loses at 5 minutes can profit at 4 hours. This reframes optimisation away from indicator tinkering.

## Learnings

- **Running the tool found a bug that 183 passing tests did not.** Executing `python -m deriv_bot.check` against the sandbox's blocking proxy raised `websockets.InvalidProxyStatus` — a `WebSocketException` that neither the check nor **the trader's reconnect loop** caught. The trader would have crashed on a rejecting proxy or a handshake failure instead of retrying, defeating the entire 24/7 design. Every test had exercised the code through fakes that raise `ConnectionLost`, so the real library's exception hierarchy was never in the picture. **Lesson: fakes verify logic, not integration boundaries.** The fix translates all socket-open failures to `ConnectionLost` inside `DerivAPI.connect`, and new tests raise the real `websockets` exception types.

- **Library background tasks can print tracebacks you never raised.** After the fix the error was handled correctly, but `websockets` still dumped a traceback from its own asyncio callback when the proxy killed the connection mid-handshake — appearing next to the clean "NOT READY" summary. Installed an asyncio exception handler routing those to DEBUG. Worth remembering: a correct error path is not the same as clean output.

- **The sandbox has no outbound access to Deriv's documentation** (proxy returns 403 on CONNECT). This turned out to improve the design: rather than encoding API details from memory that could not be verified, the bot discovers them at runtime, which is more robust against Deriv changing symbols or duration minimums.

- **Runtime discovery is the right answer to unverifiable external contracts generally.** Where a remote API's specifics cannot be confirmed, querying for them beats guessing — and the resulting code adapts to upstream change without an edit.

- **A test helper's positional parameter named `symbols` collided with a config field of the same name**, producing `TypeError: got multiple values for argument`. Renamed the helper parameter to `universe`. Worth noting because the collision was invisible until a test passed both.

- **The default strategy shows no edge on a driftless random walk — as it should.** Replaying 30,000 synthetic random-walk candles produced a 51.4% win rate over 144 trades and a net loss, because 51.4% is below the 54.1% breakeven. This is the correct result and a useful sanity check: a backtester that showed a profit on random data would be broken. It also frames the honest expectation — the strategy must find real, persistent directional structure to overcome the payout gap, and that has not been demonstrated on real data.

- **Sequencing tests around indicator warm-up is fragile if you hand-compute the exact bar a crossover lands on.** Walking a price series forward and asserting on the signals produced is both more readable and less brittle; filter tests then reuse the first signalling window and vary only the threshold under test.

- **Every strategy lost to "do nothing" on 5-minute contracts, in a market that rose 139%.** Across six real strategies and three controls on 60 days of BTC-like synthetic candles, `never_trade` topped the table. Even `always_call` lost, because over five minutes Bitcoin's drift is invisible against noise while the 0.85 payout is charged on every trade. The instrument and the horizon dominate the rule.

- **The work was lost mid-session when the container was recycled.** The branch had been re-cloned from `main` (which had moved on with an unrelated PR), so `app-src/deriv-crypto-bot/` vanished and the local branch pointed at the wrong commit. Everything pushed was intact on the remote; `git fetch origin <branch>` + `git reset --hard origin/<branch>` restored it. **Lesson: commit and push early — the remote is the only durable state in an ephemeral container.** Uncommitted in-turn work (the strategy library) had to be rewritten.
