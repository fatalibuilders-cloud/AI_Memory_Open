## Decisions

### Decision 1: AI does not create, hold, or receive API keys — guide the owner instead
- **Context:** Owner asked the AI to "do everything for the API keys," noting this is their first time creating an app.
- **Options Considered:** (a) Attempt to walk through key creation interactively in-session; (b) create a durable, beginner-friendly guide the owner can follow at their own pace, plus the storage template and security rules.
- **Decision:** Option (b) — created `API-Keys-Guide.md` at the repo root.
- **Rationale:** Keys are issued only to the account owner, logged into their own provider accounts. A committed guide survives sessions (this memory system's whole purpose) and prevents the two classic beginner failures: pasting secrets into chat, and committing secrets to git.
- **Impact:** Root file added; NextSteps items updated to reference the guide; owner unblocked with clear, ordered actions.

### Decision 2: Key creation is scheduled for the build phase, not now
- **Context:** Owner might assume keys block current progress.
- **Decision:** Guide states explicitly that staging and design require no keys; QuickBooks sandbox keys are first needed when connector development starts.
- **Rationale:** Sequencing keys to the phase that uses them reduces beginner overwhelm and avoids stale unused credentials sitting around.
- **Impact:** Staging can proceed immediately on owner review answers alone.

## Learnings

- **Learning 1:** Owner is a first-time app builder — all future communications should avoid jargon, explain the "why," and end with a short, explicit list of what the owner needs to do. Recorded in the contact profile's communication implications.
